# 06. Установщик для Windows

## 1. Что было

Воркфлоу `windows.yml` после зелёных тестов собирал переносимую папку `package-windows`
(`nuc_app.exe`, `config.toml`, `data`, `mods`, `scripts`, `RUN-ME.txt`) и складывал её в ZIP,
который уезжал в артефакты как `Nuc-lVuc-l-Windows-x64`. Установщика не было: человек получал
архив, который надо распаковать и запускать `nuc_app.exe` изнутри — при переносе папки в другое
место ярлыков, записи в «Установленные приложения» и деинсталлятора не появляется.

## 2. Требования

1. Установщик собирается **только после** успешных сборки и тестов, в том же job: упавший тест
   не должен пропускать в артефакты новый инсталлятор.
2. Он публикуется **отдельным артефактом** рядом с ZIP, а не вместо него: portable-вариант
   остаётся для тех, кому установка не нужна.
3. Версия установщика совпадает с номером прогона CI (`0.1.0.<run_number>`), чтобы по файлу
   было видно, из какого коммита он собран, и версии не повторялись между прогонами.
4. Установка даёт: копию игры в `Program Files`, ярлык в меню «Пуск», необязательный ярлык на
   рабочем столе, запись в «Установленные приложения» и работающий деинсталлятор.
5. Скрипт установщика лежит в репозитории и запускается теми же командами локально, поэтому
   его можно проверить без пуша.
6. Сборка установщика не должна удлинять job больше чем на минуту и не должна ломать
   существующие артефакты.

## 3. Реализация

`installer/vcv.iss` — скрипт Inno Setup 6. Три вещи в нём задаются снаружи через `/D`, поэтому
файл не знает ни путей CI, ни номера прогона:

| Define | Смысл | Значение по умолчанию |
|---|---|---|
| `StageDir` | папка с уже собранной portable-сборкой | `..\package-windows` |
| `AppVersion` | версия в свойствах файла и в «Установленные приложения» | `0.1.0-dev` |
| `OutDir` | куда положить `V-C-V-Setup-x64.exe` | `dist` |

`AppId` жёстко зафиксирован: по нему Windows отличает обновление от второй установки, поэтому
менять его нельзя — иначе пользователь получит две копии в списке программ.

В `windows.yml` добавлены три шага после «Upload Windows package»:

1. `choco install innosetup` — на образе `windows-2022` его нет.
2. `ISCC.exe` с тремя `/D` — проверка `$LASTEXITCODE` обязательна, иначе упавшая компиляция
   оставит job зелёным, а артефакт пустым.
3. `upload-artifact` с `path: dist/V-C-V-Setup-x64.exe` и `if-no-files-found: error`.

## 4. Проверка

| Что | Как |
|---|---|
| Скрипт компилируется | `ISCC.exe` возвращает 0, в `dist/` появляется `V-C-V-Setup-x64.exe` |
| Версия попадает в файл | у exe в свойствах `ProductVersion` равен переданному `AppVersion` |
| Артефакт доезжает | в API прогона есть артефакт `V-C-V-Installer-Windows-x64` ненулевого размера |
| Игра внутри | установщик ставит `nuc_app.exe`, `data`, `mods`, `scripts`, `config.toml` |
| Установка работает | запуск установленного `nuc_app.exe` из `Program Files` открывает окно |

## 5. Риски

| Риск | Что делаем |
|---|---|
| `choco install innosetup` меняет версию между прогонами | пин версии в команде и явная проверка наличия `ISCC.exe` |
| Установка в `Program Files` требует прав | `PrivilegesRequired=lowest`: игра ставится в `%LOCALAPPDATA%\Programs\V-C-V` без UAC, зато только для текущего пользователя |
| `world.save` рядом с exe остаётся после удаления | так и задумано: сохранения не удаляем вместе с программой |
| Артефакт весит десятки мегабайт | `retention-days: 30`, LZMA2, ZIP остаётся легче |

## 6. Результат

Заполняется после зелёного прогона CI с установщиком.

### 6.1. Локальная проверка (2026-10-23, Inno Setup 6.7.3, Windows 11)

| Что проверили | Итог |
|---|---|
| Компиляция скрипта | `Successful compile (0,735 sec)` |
| Размер установщика | **2.4 МБ** для 17 файлов staging-папки |
| Метаданные exe | `FileVersion` и `ProductVersion` = переданному `0.1.0.0`, `ProductName` = `V-C-V` |
| Установка файлов | **18 файлов** скопировано (17 + `unins000.exe`) до шага ярлыков |
| Ярлык в «Пуск» | **отказано в доступе** — песочница хоста запрещает дочерним процессам писать в `%APPDATA%\...\Start Menu` |
| Запись в реестр | **отказано в доступе** — `RegCreateKeyEx HKCU\...\Uninstall\{...}_is1` |
| Откат после сбоя | сработал корректно: скопированные файлы удалены, каталог установки убран |

Отказы — ограничение окружения, а не установщика: тот же процесс PowerShell из этой сессии
пишет и в `HKCU`, и в «Пуск» без ошибок, а дочернему процессу запрещено. Поэтому установка
проверяется на раннере GitHub Actions, где таких ограничений нет: шаг
«Smoke-install the produced installer» ставит игру молча, проверяет наличие `nuc_app.exe`,
запускает деинсталлятор и падает, если тот оставил файлы.

Ошибка, найденная компилятором: `VersionInfoVersion` принимает только четыре числовых
компонента, поэтому `0.1.0-local` отклоняется, а `0.1.0.<run_number>` проходит. Это записано
комментарием в шапке `installer/vcv.iss`.

Вторая ошибка, найденная при первом локальном прогоне: с `PrivilegesRequired=admin` установка
из неэлевированной сессии завершается кодом 1 ещё до логирования. Переключил на
`PrivilegesRequired=lowest` — игра ставится в `%LOCALAPPDATA%\Programs\V-C-V` без UAC, и
установщик хотя бы доходит до шага ярлыков (что и видно в таблице выше).
