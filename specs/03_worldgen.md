# Фаза W — генерация мира

Статус: черновик к исполнению, 2026-10-23. Предшественники: B1 (пресеты, вендорная Lua), T (текстуры).
Задача фазы: заменить «холм из одного шума» на мир с биомами, пещерами и рудными жилами, не потеряв детерминизм и инкрементальность. Сеть, физика и LOD в эту фазу не входят.

## 1. Что есть сейчас и чем это плохо

`world/generator.cpp` (43 строки) делает ровно три вещи: берёт один слой OpenSimplex2, округляет высоту, ставит `камень/земля/трава` и заливает воду до `sea_level`.

- **Биомы не влияют на рельеф.** `data/biomes.json` описывает `temperate` и `arid` с разными рудами, но `ResourceGenerator::apply` выбирает биом хешем региона, а не координатой: соседние чанки внутри региона получают случайный набор руд, а сам биом никак не виден на поверхности.
- **Пещер нет.** Мир сплошной, копать некуда.
- **Руды появляются «по одной воксели»** с вероятностью 1.8 % на воксель камня: жил как структур нет, зато есть просадка производительности на каждом вокселе диапазона.
- **`world/gen_resources.cpp` — 10 строк, но это две строки по 4000 символов.** Читать, тестировать и расширять это нельзя, поэтому фаза W переписывает модуль целиком.

## 2. Требования

1. **Детерминизм.** Мир — чистая функция `(seed, world_x, world_y, world_z)`. `generate()` дважды на одинаковых координатах даёт одинаковые воксели; `state_hash` чанка не зависит от порядка генерации и от количества потоков (проверяется в фазе M).
2. **Непрерывность на границах чанков.** Высота соседних колонок по обе стороны шва различается не больше чем на 3 блока: рельеф, пещеры и биом считаются по мировым координатам, а не по локальным индексам.
3. **Биомы видны и согласованы.** `temperate` (трава, руда меди) и `arid` (голая земля, руда железа) определяются низкочастотным шумом температуры; биом одного столбца не зависит от того, в каком чанке его запросили.
4. **Пещеры не ломают поверхность.** Пещера вырезается только в камне, не выше `surface - 4` и не ниже `y = 2`, не затрагивает воду и не оставляет висящих блоков над собой.
5. **Рудные жилы — структуры.** Жила задаётся правилом из `data/biomes.json` (руда, материал-хозяин, размер, диапазон высот) и раскладывается случайным блужданием внутри чанка, поэтому не рвётся на швах и не стоит `O(объём × правила)`.
6. **Производительность.** Генерация одного чанка 32³ — не дороже 6 мс в Release; девять чанков стартового квадрата — меньше 250 мс суммарно (с запасом на Debug и ASan).
7. **Совместимость.** Сохранения читаются как раньше: генератор не меняет формат `world.save`, сид по-прежнему берётся из сохранения. Существующие тесты `tests/test_generator.cpp` остаются зелёными (утверждение про траву уточняется: трава обязана быть в чанке temperate-биома).

## 3. Модули и интерфейсы

Каждый файл — одна ответственность, меньше 200 строк.

### 3.1 `world/biome.h` / `biome.cpp`

```cpp
namespace nuc::world {
enum class Biome : std::uint8_t { temperate = 0, arid = 1 };
inline constexpr std::size_t biome_count = 2;

struct BiomeProfile {
    std::uint32_t surface{};      // материал верхнего блока
    std::uint32_t subsurface{};   // материал трёх блоков под верхним
    float height_bias{};          // сдвиг высоты, блоки
    float amplitude_scale{1.0F};  // множитель амплитуды
};

[[nodiscard]] BiomeProfile biome_profile(Biome biome) noexcept;
[[nodiscard]] const char* biome_name(Biome biome) noexcept;  // "temperate" / "arid"
[[nodiscard]] Biome biome_from_name(std::string_view name) noexcept;  // неизвестное → temperate
}
```

`temperate`: `grass` сверху, `soil` под ним, смещение 0, амплитуда 1.0. `arid`: `soil` сверху, `stone` под ним, смещение +2, амплитуда 0.6 — так биомы различимы силуэтом, а не только цветом.

### 3.2 `world/terrain_shape.h` / `terrain_shape.cpp`

```cpp
namespace nuc::world {
struct ColumnSample { float height{}; Biome biome{Biome::temperate}; };

class TerrainShape final {
public:
    explicit TerrainShape(GeneratorSettings settings);
    [[nodiscard]] ColumnSample sample(std::int64_t world_x, std::int64_t world_z) const;
private:
    GeneratorSettings settings_;
    FastNoiseLite continent_;
    FastNoiseLite hills_;
    FastNoiseLite temperature_;
};
}
```

- `continent_`: OpenSimplex2, частота `frequency`, 4 октавы, вес 0.65 — крупные формы.
- `hills_`: OpenSimplex2, частота `frequency * 3.5`, 3 октавы, вес 0.35 — детализация.
- `temperature_`: OpenSimplex2, частота `frequency * 0.25` — биом; порог `0.05` разделяет `temperate` и `arid`, поэтому границы биомов — плавные кривые, а не сетка.
- `height = base_height + amplitude * amplitude_scale * (0.65*continent + 0.35*hills) + height_bias`.

`sample()` — `const`, без внутреннего состояния: один экземпляр можно звать из нескольких потоков (важно для фазы M).

### 3.3 `world/cave_carver.h` / `cave_carver.cpp`

```cpp
class CaveCarver final {
public:
    explicit CaveCarver(GeneratorSettings settings);
    [[nodiscard]] bool is_cave(std::int64_t world_x, std::int64_t world_y, std::int64_t world_z) const;
private:
    GeneratorSettings settings_;
    FastNoiseLite tunnel_a_;
    FastNoiseLite tunnel_b_;
};
```

Пещера там, где **оба** поля близки к нулю: `|a| < density && |b| < density` — это пересечение двух изоповерхностей, то есть вытянутые туннели, а не «дырки по всему объёму». `density` берётся из `GeneratorSettings::cave_density` (по умолчанию `0.055`). Частоты 3D-шумов — `frequency * 1.6` по всем осям, `y` масштабируется вдвое сильнее, чтобы туннели были положе и не превращались в вертикальные колодцы.

### 3.4 `world/generator.h` / `generator.cpp`

```cpp
struct GeneratorSettings {
    std::int32_t seed{1337};
    float frequency{0.035F};
    float base_height{14.0F};
    float amplitude{7.0F};
    std::int32_t sea_level{8};
    float cave_density{0.055F};
};

class ChunkGenerator final {
public:
    explicit ChunkGenerator(GeneratorSettings settings = {});
    [[nodiscard]] Chunk generate(std::int32_t chunk_x, std::int32_t chunk_z) const;
    [[nodiscard]] Biome biome_at(std::int64_t world_x, std::int64_t world_z) const;
    [[nodiscard]] const GeneratorSettings& settings() const noexcept;
private:
    GeneratorSettings settings_;
    TerrainShape shape_;
    CaveCarver caves_;
};
```

Порядок сборки столбца: высота → слои (`stone` ниже `h-3`, `subsurface` в `h-3..h-1`, `surface` в `h`) → вода до `sea_level` → пещеры (`y` от 2 до `h-4`, только в твёрдом, только выше `sea_level + 1`) → ничего больше. Руды накладывает `ResourceGenerator` в `app/main.cpp`, чтобы генератор оставался про рельеф.

Валидация настроек прежняя плюс `cave_density` в диапазоне `(0; 0.5)`.

### 3.5 `world/gen_resources.h` / `gen_resources.cpp` (переписывается)

```cpp
struct ResourceRule { std::uint32_t id{}, source_material{}; double chance{}; std::uint32_t vein_size{1}; int min_y{}, max_y{31}; };
struct BiomeResourceRule { std::string id; int region_chunks{4}; std::vector<ResourceRule> resources; };

class ResourceGenerator final {
public:
    void load(const std::filesystem::path& path);                       // как раньше, но с читаемым разбором
    void apply(Chunk& chunk, std::uint64_t seed, Biome biome) const;    // новый основной вход
    void apply(Chunk& chunk, std::uint64_t seed) const;                 // совместимость: биом по региону
    [[nodiscard]] const std::vector<BiomeResourceRule>& biomes() const noexcept;
    [[nodiscard]] const BiomeResourceRule* rule_for(Biome biome) const noexcept;
};
```

Алгоритм `apply(chunk, seed, biome)`: `attempts = 32` попыток на чанк, PRNG — `splitmix64(mix(seed) ^ mix(cx) ^ mix(cz))`; на попытку выбирается правило биома, `y` из `[min_y, max_y]`, точка `(x, z)` в чанке; если воксель — `source_material`, то ставится руда и от неё идёт блуждание на `vein_size - 1` шаг по шести направлениям (только в `source_material`, только в диапазоне высот). Всё, что выходит за границы чанка, отбрасывается — жила не перетекает в соседний чанк, поэтому швов нет.

## 4. Тесты (`tests/test_worldgen.cpp`, 8 кейсов)

| Кейс | Что доказывает |
|---|---|
| W1 высота непрерывна на шве чанков | для 64 пар колонок по обе стороны `x = 32` и `z = 32` разница высот ≤ 3 |
| W2 биом пространственно связен | в области 64×64 встречаются оба биома, и внутри блока 8×8 биом одинаков не меньше чем у 90 % пар |
| W3 биом не зависит от чанка | `generator.biome_at(wx, wz)` совпадает для запроса из чанка и напрямую |
| W4 пещеры не ломают корку | в каждом столбце 3 верхних блока под поверхностью твёрдые; нет воздуха ниже `y = 2`; в 3×3 чанках есть хотя бы одна пещерная пустота |
| W5 пещеры детерминированы | `is_cave` дважды и после генерации чанка даёт те же значения |
| W6 руды — жилы | на каменном чанке 1..N рудных вокселей, все в диапазоне правила, руда не заменяет воздух, повторный вызов даёт тот же результат |
| W7 генерация детерминирована | `generate` дважды равен, разные сиды различаются, FNV-1a хэш вокселей совпадает |
| W8 вода и поверхность | ниже `sea_level` над землёй стоит вода, трава не появляется под водой |

Плюс правка `tests/test_generator.cpp`: утверждение «в чанке есть трава» заменяется на «в чанке temperate-биома есть трава и камень».

## 5. Риски

| Риск | Смягчение |
|---|---|
| Пещеры «съедят» стартовую площадку под ногами | корка 4 блока от поверхности и запрет вырезать ниже `y = 2`; проверяется W4 |
| Дорогой 3D-шум на каждый воксель | пещеры считаются только для `y` в `[2, h-4]`, то есть для ~40 % объёма, и только после отсечения воды |
| Биом «мигает» на границе | порог по низкочастотному шуму и тест W2 на связность |
| `gen_resources` переписан и потерял совместимость с `world.save` | формат сохранения не трогаем; `ResourceGenerator::apply(chunk, seed)` остаётся как совместимый вход |
| Генерация станет медленнее 20-секундного бюджета сборки | это рантайм, не сборка; бюджет W6 — 6 мс на чанк, замеряется тестом |

## 6. Результат (2026-10-23)

| Проверка | Факт |
|---|---|
| `windows-release`: build + `ctest` | **134/134 passed** (9 новых кейсов W1–W9, прежние 125 без изменений) |
| Девять чанков стартового квадрата | **6 мс** на все девять (≈0.7 мс на чанк) при бюджете 250 мс |
| Непрерывность рельефа | 128 пар колонок по обе стороны швов `x=0` и `z=0`, максимальная разница высот укладывается в 3 блока |
| Пещеры | корка из 4 блоков над пустотой не пробивается ни в одном столбце 3×3 чанков; пустоты ниже корки есть |
| Руды | на каменном чанке медь появляется жилой в диапазоне `min_y..max_y`, повторный вызов даёт тот же чанк, на воздухе не появляется ничего |
| Скриншот | `specs/img/worldgen.png`: 5 785 зелёных (трава) и 40 591 «прочих» (камень/земля) пикселей против 16 зелёных при прежних настройках — поверхность стала землёй, а не океаном |

Что уточнилось по ходу:

1. **Высоту пришлось поднять, а уровень моря опустить** (`base_height` 12 → 14, `amplitude` 8 → 7, `sea_level` 10 → 8). С прежними числами шум давал среднюю высоту 12 при море 10, и стартовый квадрат оказывался в воде: на скриншоте было 16 зелёных пикселей из 245 тысяч. Теперь суша доминирует, а вода осталась в низинах.
2. **Смешивание биомов сделано плавным.** Изначально биом должен был добавлять к высоте константу (`+2` для `arid`), но тогда на границе биомов получался уступ до 5 блоков и тест непрерывности W1 не мог быть честным. Теперь смещение и амплитуда интерполируются по температуре в полосе ±0.15 вокруг порога, а биом (для материалов) выбирается по самому порогу.
3. **Пещеры не ограничены уровнем моря.** В спецификации стояло «только выше `sea_level + 1`», но при средней высоте 14 это отрезало бы почти все пещеры. Вода заливается только выше поверхности столбца, поэтому подземная пустота ниже уровня моря остаётся сухой и корректной.
4. **Тест W8 задаёт уровень моря явно** (`.sea_level = 13`), иначе после настройки мира вода у старта почти исчезает и кейс перестаёт что-либо проверять.
5. **Камера поднята с `y = 18` до `y = 24`**: прежняя позиция оказывалась внутри холмов новой высоты.
